Machine Unlearning

Suppose a hospital helped train a diagnostic model and later asks for its patients’ records to be removed. Deleting the files prevents their use in future training. It does not change the model already trained on them. The model may still make predictions differently because those records were present, and it may reveal details about them. Machine unlearning studies how to remove that training influence while keeping the model useful. Cao and Yang's early work helped establish this problem.

The most direct solution is to train again using only the permitted data. That gives us both a valid method and a reference against which faster methods can be judged. The difficulty is to save computation without silently weakening the claim. This article builds that comparison carefully, then follows it through centralised learning, federated learning, language models, evaluation, and repeated deletion requests.

Each chapter ends where our own work sits. The figures are all from our papers, one per chapter, and they are there for a specific reason: a definition tells you what has to be true, but it does not tell you what the system looks like when you try to satisfy it on a real deployment. The figures show that second thing. None of them is evidence that the definition was met.

Start with the assumption the definition quietly makes. Writing \(\mathcal{D}^{\textrm{f}}\) for the forget set presumes someone can name its records. Often nobody can. An operator sees that something is wrong downstream and has to work backwards to the data, as in .

The same gap appears whenever a dataset contains incorrect labels, a participant leaves a training collaboration, or an operator discovers poisoned examples. These requests are related, but their success criteria differ. Repairing accuracy after poisoning is not automatically evidence that every effect of the poisoned records has been removed.

What does it mean for a model to forget?

Start with the data and the training procedure

Let \(\mathcal{D}\) be the original training dataset. A request specifies the forget set \(\mathcal{D}^{\textrm{f}} \subseteq \mathcal{D}\); the retain set is \(\mathcal{D}^{\textrm{r}}=\mathcal{D}\setminus\mathcal{D}^{\textrm{f}}\). Here records have identities: two identical-looking records can still be separate training examples. Unless stated otherwise, the retain set is nonempty.

Write \(\mathcal{A}\) for the complete training procedure and \(\boldsymbol{\theta}^{\textrm{old}}=\mathcal{A}(\mathcal{D})\) for its trained parameters. The word complete matters. The architecture, preprocessing, optimiser, stopping rule, and distribution of random seeds are all part of the reference procedure. Changing them only for the retrained baseline changes the question being tested.

The following table fixes the notation used throughout. Bold Latin letters denote vectors or matrices; bold Greek letters denote Greek vectors. Time goes in square brackets, entity indices in subscripts, and identity tags in upright superscripts, following the site's notation rules.

SymbolMeaning
\(\mathcal{D},\mathcal{D}^{\textrm{f}},\mathcal{D}^{\textrm{r}}\)Original, forget, and retain datasets; tags f and r abbreviate forget and retain.
\(\mathcal{A},\mathcal{U}\)Training and unlearning algorithms.
\(\boldsymbol{\theta}^{\textrm{old}},\boldsymbol{\theta}^{\textrm{unl}},\boldsymbol{\theta}^{\star}\)Original, unlearned, and retrained model parameters.
\(f(\mathbf{x};\boldsymbol{\theta})\)Model prediction for input vector \(\mathbf{x}\); \(y\) is its target label.
\(\mathcal{S};\epsilon,\delta\)A measurable set of model parameters; nonnegative multiplicative budget and additive probability slack, with \(0\leq\delta<1\).
\(\mathcal{D}_k; k,N\)Client \(k\)'s dataset; client index and total number of clients.
\(\boldsymbol{\theta}[t]; t,T\)Global parameters at round \(t\); round index and total training rounds.
\(\mathbf{g}^{\textrm{r}},\mathbf{H}^{\textrm{r}}\)Gradient and Hessian of the retain objective, evaluated at \(\boldsymbol{\theta}^{\textrm{old}}\).
\(\mathcal{Q}^{\textrm{f}},\mathcal{Q}^{\textrm{r}}\)Forget and utility query sets for evaluating a language model.

For now, consider a centralised setting in which the unlearning algorithm can access both data subsets. Its output and reference are

\[ \begin{aligned} \boldsymbol{\theta}^{\textrm{unl}}&=\mathcal{U}(\boldsymbol{\theta}^{\textrm{old}},\mathcal{D},\mathcal{D}^{\textrm{f}}),\\ \boldsymbol{\theta}^{\star}&=\mathcal{A}(\mathcal{D}^{\textrm{r}}). \end{aligned} \]

This interface describes available information, not a requirement to read every record. Some methods also retain checkpoints or training statistics. Those are additional algorithm state and must be included in the storage cost and, when relevant, in the guarantee. Later chapters explain what changes when the server cannot access the data, and what changes when it cannot even reread the forget set.

Why the reference is a distribution

Random initialisation, minibatch ordering, and other training randomness can produce different weights from the same dataset. Thus \(\boldsymbol{\theta}^{\star}\) is generally a random variable. The comparison concerns the distribution induced by repeated runs of the specified algorithm, not equality with one conveniently chosen checkpoint. A deterministic algorithm is the special case in which all probability is concentrated on one output.

This has a consequence worth stating plainly, because it is the single most common misreading of the field. Removing a training influence need not restore the particular weights that existed before the record was learned. Training does not have an undo button, and rewinding to an old checkpoint is a different operation from retraining without a record. Another valid training run on the retained data can end somewhere else entirely, and that is not a failure.

Definition 1 (Exact unlearning, one fixed request). For a specified training algorithm \(\mathcal{A}\), the algorithm \(\mathcal{U}\) achieves exact unlearning if, for every admissible dataset and forget set, \[ \boldsymbol{\theta}^{\textrm{unl}}\stackrel{\textrm{d}}{=}\boldsymbol{\theta}^{\star}. \] The symbol \(\stackrel{\textrm{d}}{=}\) means equality in distribution: both outputs fall in every measurable set \(\mathcal{S}\) with the same probability. Probability is taken over the algorithms' randomness, with the data and request held fixed.

This distributional view is developed in work such as Ginart et al. and Bourtoule et al.. Full retraining satisfies it directly. An efficient exact method must reproduce the reference distribution with less work, for example by updating sufficient statistics or retraining only independent components. Exactness is always relative to the specified \(\mathcal{A}\); it does not mean that every learning pipeline should produce the same model.

Approximate guarantees and what an observer sees

Definition 2 (Two-sided \((\epsilon,\delta)\)-unlearning). For every admissible fixed dataset and request, and every measurable set of parameters \(\mathcal{S}\), require both \[ \begin{aligned} \Pr[\boldsymbol{\theta}^{\textrm{unl}}\in\mathcal{S}]&\leq e^{\epsilon}\Pr[\boldsymbol{\theta}^{\star}\in\mathcal{S}]+\delta,\\ \Pr[\boldsymbol{\theta}^{\star}\in\mathcal{S}]&\leq e^{\epsilon}\Pr[\boldsymbol{\theta}^{\textrm{unl}}\in\mathcal{S}]+\delta. \end{aligned} \] Here \(\epsilon\geq0\) bounds a multiplicative discrepancy and \(0\leq\delta<1\) permits additive probability slack. This is a model-output guarantee for a single request fixed independently of training randomness.

An event \(\mathcal{S}\) can represent the set of models on which an observer declares, “this looks unlearned rather than retrained.” The inequalities constrain every such measurable decision rule. Smaller budgets mean a stronger comparison; \(\epsilon=\delta=0\) gives exact equality. The additive term is not a fraction of training records that may be ignored. Nor do the inequalities mean that predictions must agree on every input in a particular pair of runs.

Certified-removal and theoretical unlearning papers use this kind of distributional comparison, with differences in the permitted requests, state, and assumptions. A paper that reports similar test accuracy alone has not established Definition 2. If the attacker also sees old model versions, checkpoints, or intermediate messages, the observable object is larger than the final parameter vector and needs its own analysis.

Differential privacy helps explain the form of the bound. If \(\mathcal{A}\) is differentially private under add-or-remove-one-record adjacency, keeping its output unchanged already satisfies the corresponding comparison for one fixed record deletion. Deleting a whole client or a large group requires a group guarantee, whose budgets generally worsen with group size. This observation does not make a record-level privacy guarantee a free client-level deletion guarantee, and it says nothing by itself about removing stored copies of the raw data.

Decide what the request actually removes

A sample request identifies records. A class request identifies all training examples with a chosen label. A client request identifies one participant's local records. They can all be expressed as choices of \(\mathcal{D}^{\textrm{f}}\), but their size and relation to the remaining data differ substantially, and a method that handles one well can fail badly on another. A client request removes a correlated block of data that one party collected; a class request removes a concept that the remaining data may still partly support; a sample request removes points that look like thousands of retained neighbours.

Feature and label correction need a slightly different reference. If a user withdraws one sensitive field while allowing other fields to remain, deleting the entire row may discard too much. The target dataset contains edited records, and the reference should be training on that edited dataset. Warnecke et al. study this distinction explicitly. One should specify this transformation before comparing algorithms.

Granularity also interacts with the modality. When a model aligns images with text, a record is a pair, and the alignment it taught can survive in either branch after the pair is gone. is our attempt at closing those residues in a federated multimodal model, and its top-right panel is a compact statement of the three request types just listed.

How centralised methods save work

SISA: make the affected part small

SISA stands for Sharded, Isolated, Sliced, and Aggregated. It changes the training procedure before any deletion arrives. Split the records into disjoint shards, train a separate constituent model on each shard, and aggregate their predictions. Within a shard, introduce data in successive slices and save a checkpoint before each new slice is used.

When a record is deleted, locate its shard and its earliest affected slice. Restore a checkpoint from before that record entered training, then rerun the affected suffix without the record. The other shard models can be reused. If several records are deleted, every affected shard must be repaired, starting before the earliest affected slice in that shard.

For an intuitive example, imagine ten equally expensive shards and one deletion in one shard. Only that constituent model needs repair; slicing may reduce its cost further. This is a workload illustration, not a universal tenfold wall-clock speedup. Parallelism, checkpoint loading, aggregation, and the location of the record all affect elapsed time.

The exactness claim compares against the same SISA training procedure on the retained records, with consistent partition, randomisation, and checkpoint semantics. It is not equality with a single neural network trained on the whole retained dataset. Preprocessing shared across shards must also avoid retaining the deleted record's influence. SISA pays for deletion efficiency through checkpoint storage, ensemble inference, and potentially weaker constituent models because each sees less data.

A Newton update: estimate how the optimum moves

Another approach starts with the original model and estimates how its optimum changes after deletion. To make the calculation precise, let \(\mathcal{B}\) denote a nonempty dataset and define

\[ \mathcal{J}(\boldsymbol{\theta};\mathcal{B})= \frac{1}{|\mathcal{B}|}\sum_{(\mathbf{x},y)\in\mathcal{B}}c(\boldsymbol{\theta};\mathbf{x},y) +\frac{\lambda}{2}\|\boldsymbol{\theta}\|_2^2. \]

Here \(c\) is the per-example loss, \(\lambda>0\) controls quadratic regularisation, and \(\|\cdot\|_2\) is the Euclidean norm. Write \(\mathcal{J}^{\textrm{r}}(\boldsymbol{\theta})=\mathcal{J}(\boldsymbol{\theta};\mathcal{D}^{\textrm{r}})\) for the retain objective. For this local argument, assume it is twice differentiable and strongly convex, and treat \(\boldsymbol{\theta}^{\textrm{old}}\) as an accurately optimised starting point. Define its retain gradient and Hessian as

\[ \mathbf{g}^{\textrm{r}}=\nabla\mathcal{J}^{\textrm{r}}(\boldsymbol{\theta}^{\textrm{old}}),\qquad \mathbf{H}^{\textrm{r}}=\nabla^2\mathcal{J}^{\textrm{r}}(\boldsymbol{\theta}^{\textrm{old}}). \]

The gradient measures how far the old model is from stationarity on the retained data. The Hessian measures local curvature. Linearising the retain gradient and setting that approximation to zero gives the Newton candidate

\[ \boldsymbol{\theta}^{\textrm{new}}= \boldsymbol{\theta}^{\textrm{old}}-(\mathbf{H}^{\textrm{r}})^{-1}\mathbf{g}^{\textrm{r}}. \]

This is the general optimisation intuition behind influence-based removal, not a transcription of Guo et al.'s certified algorithm. Even in a convex problem, one Newton step need not reach the exact retain optimum. The remaining gradient, approximation errors, and the original training error all matter. In a large neural network, strong convexity and an affordable invertible Hessian are usually unavailable, so this derivation alone supplies no certificate.

Guo et al. combine a removal update with random perturbation and a bound on the remaining gradient to obtain certified removal for their stated model class. The certificate depends on how the model was trained and how that residual is controlled. Adding arbitrary noise to an arbitrary edited model is insufficient.

When the forget data cannot be read again

Every method so far assumes the forget data is still there to be computed on. Gradient ascent needs it, the Newton update needs a gradient and a curvature estimate on it, and SISA needs to know which slice it entered. Quantum federated learning breaks that assumption at the physical level: a quantum state is destroyed by the measurement that reads it, and the no-cloning theorem means no copy was kept. When the request arrives, the data it names no longer exists in any form the node can evaluate.

That forces a different order of operations. The quantities needed at deletion time have to be recorded during training, before the state is consumed, and they have to be cheap enough to store for every training state. In each node writes a classical shadow of every training state as it goes, and the forget gradient and curvature are later estimated from those shadows at whatever parameters the model has reached by then. The Newton step above is then applied in its federated form, with only classical estimates crossing the network.

The general lesson survives the exotic setting. Whenever the forget data will be unavailable at deletion time, for legal, physical, or retention-policy reasons, the information needed to remove it has to be budgeted during training. That stored state is part of the algorithm and belongs in both the cost accounting and, when a guarantee is claimed, in the analysis of what an observer can see.

Gradient ascent and SCRUB: change behaviour while retaining utility

For deep models, many practical methods use loss-based updates without a distributional certificate. Define the average forget loss \(\mathcal{J}^{\textrm{f}}\) by averaging \(c\) over \(\mathcal{D}^{\textrm{f}}\), without the regulariser. Gradient ascent takes steps of the form

\[ \boldsymbol{\theta}[t+1]=\boldsymbol{\theta}[t]+\eta\nabla\mathcal{J}^{\textrm{f}}(\boldsymbol{\theta}[t]),\qquad \eta>0. \]

Here \(t\) indexes optimisation steps and \(\eta\) is the step size. Increasing the loss makes the deleted examples harder to predict. But the same parameters support other examples, so this can damage useful behaviour. It can also make deleted records unusually easy to identify because their loss becomes abnormally high.

SCRUB addresses the utility trade-off with a teacher and a student. The teacher is the frozen original model; the student starts from its weights. On retained examples, the student is encouraged to match the teacher and predict the true labels. On forget examples, it is pushed away from the teacher. The algorithm alternates these updates and performs additional retain updates. SCRUB+R selects an earlier checkpoint to avoid excessive forget error in privacy-oriented applications. These are concrete training and checkpoint-selection rules, not proofs of Definition 2.

Other approaches store and reverse selected training updates or modify weights using curvature information. Their key question is the same: which dependencies are actually removed, and which are only approximated? Subtracting an old update does not undo all later updates computed from the model it changed.

Federated learning: access changes the algorithm

Define the federated reference first

In federated learning, \(N\) clients train a model \(f(\cdot;\boldsymbol{\theta})\) while retaining their local datasets \(\mathcal{D}_k\). Let \(\mathcal{D}=\bigcup_{k=1}^{N}\mathcal{D}_k\) denote the union of all local datasets, with record identities distinguishing copies held by different clients. Let \(k^{\textrm{f}}\) identify the departing client. Its client-level request sets \(\mathcal{D}^{\textrm{f}}=\mathcal{D}_{k^{\textrm{f}}}\). The retraining reference reruns the stated federated protocol without those records and without that client's training contribution.

For a simple full-participation example, let \(\boldsymbol{\Delta}_k[t]\) be client \(k\)'s local parameter change after starting from \(\boldsymbol{\theta}[t]\). Let \(\omega_k=|\mathcal{D}_k|/|\mathcal{D}|\) be its aggregation weight. The server update is

\[ \boldsymbol{\theta}[t+1]=\boldsymbol{\theta}[t]+\sum_{k=1}^{N}\omega_k\boldsymbol{\Delta}_k[t]. \]

The index \(k\) ranges over clients and \(t=0,\ldots,T-1\) indexes rounds. Removing client \(k^{\textrm{f}}\) changes the aggregation weights and the model received by every remaining client in later rounds. Therefore the recorded \(\boldsymbol{\Delta}_k[t]\) generally differs from the update client \(k\) would have computed in a run where client \(k^{\textrm{f}}\) had never participated. This is why deleting the target's saved updates is not generally exact unlearning.

What FedEraser reuses, and what it recomputes

FedEraser stores historical client updates and uses remaining clients to calibrate updates during reconstruction. Roughly, the saved updates provide information about update magnitudes, while new local computation supplies directions appropriate to the reconstructed trajectory. It trades server storage and additional client participation for less computation than complete retraining.

The protocol assumptions deserve as much attention as the optimisation. Are remaining clients available? Are individual historical updates stored, or does secure aggregation expose only their sum? Is the departing client willing to participate once more? These conditions determine whether a method can even be run.

For example, Wu et al. combine subtraction of historical contributions with knowledge distillation, using unlabelled auxiliary data for recovery rather than requiring client data. Halimi et al. first perform local unlearning at the departing client, then run recovery rounds with the remaining clients. It would be misleading to describe the latter as requiring only the departing client's computation. Neither protocol should inherit a centralised guarantee merely because both edit model weights.

Edit the layers that carry the knowledge

The methods above treat the model as one object. A second line of work asks where in the model a client's contribution actually lives, on the view that rewriting the whole parameter vector to remove one client's influence is more surgery than the request needs. Which layers moved most while that client was participating is a question the server can answer from the history it already keeps.

Granularity has a price on the other side too. At the mobile edge the model is serving traffic while it is being repaired, so the relevant cost is not only computation but staleness: how old the knowledge in the deployed model is while unlearning runs. makes that trade explicit, scoring layers by a client's historical contribution and then editing weight subgroups inside the selected layers rather than retraining them.

When a record is not a row

With a graph model, deleting a node also changes the edges and neighbourhoods through which other nodes receive messages. The reference must state whether the request removes the node, its incident edges, its features, or a particular training label. GraphEraser adapts partition-and-retrain ideas to this structured setting.

A recommendation system has a similar dependency through user-item interactions. Removing one interaction is different from removing an entire user and all of that user's interactions. Federated on-device recommendation combines this structure with restricted access to local data. These cases explain why a row-deletion method cannot be transferred simply by renaming its dataset.

Physical measurements push this further, because there the artefact being maintained is not even a set of weights. A channel knowledge map is built from uplink pilots contributed by many terminals, and it is a map: each cell of it was estimated from reports that are long gone by the time anyone asks for them back. A request such as “forget what terminal 3 contributed in the lower band” names a region of that map, not a row of a table, as shows, and the only honest way to repair the region is to measure it again.

Over-deletion deserves a general comment. A method that removes more than was requested will pass most forgetting metrics easily, because forgetting metrics only ask whether the target is gone. It is the retain-side and utility measurements that notice the damage, which is one reason the evaluation chapter below insists on reporting both against the same reference.

Language models: deleting records and removing knowledge

The definition still applies; obtaining the reference is harder

A language model can be asked to forget a known fine-tuning subset, a person's private details, a document, or a capability. These are not interchangeable targets. If the training records are known, the same retraining definition remains meaningful. For a broad concept, however, the relevant evidence may occur in many documents, paraphrases, and languages. Even identifying \(\mathcal{D}^{\textrm{f}}\) becomes part of the problem.

It is useful to separate a mathematical reference from a reference we can afford to construct. Retraining a large base model may be impractical, but that does not make \(\mathcal{A}(\mathcal{D}^{\textrm{r}})\) undefined. Controlled fine-tuning tasks can construct a reference and are particularly helpful for studying this gap.

TOFU is such a task. It introduces fictitious author profiles through fine-tuning and selects some authors for deletion. A retain-only model is fine-tuned from the same starting checkpoint without those authors. This is a controlled reference for the added fine-tuning information; it is not a claim to know every fact present in pretraining.

What the loss is trying to change

Let \(q\) be a prompt and \(y\) a target answer sequence. We continue to use \(y\) for the prediction target, now a text sequence rather than a class label. Write \(p_{\boldsymbol{\theta}}(y\mid q)\) for the model's conditional probability of that sequence, obtained from its token probabilities. The negative log-likelihood is

\[ c(\boldsymbol{\theta};q,y)=-\log p_{\boldsymbol{\theta}}(y\mid q). \]

This is the language-model instance of the per-example loss introduced earlier. Gradient ascent on forget examples lowers the probability of their target answers. Without a retain objective or another constraint, it can also impair language generation well beyond the requested material.

Negative preference optimisation uses the original model as a reference and changes the update pressure as the unwanted answer becomes less likely. It is designed to improve the forgetting-utility trade-off over plain ascent. Its objective is not a universal proof that knowledge has been erased. Other approaches construct replacement targets, as in the Harry Potter study, or alter internal representations, as in the representation-misdirection method evaluated with WMDP. Their training targets need to be judged against the particular deletion or capability-removal goal.

Query-based evaluation is useful but narrower

Let \(\mathcal{Q}^{\textrm{f}}\) contain prompts intended to elicit the target material and \(\mathcal{Q}^{\textrm{r}}\) contain prompts testing useful capabilities. These are evaluation queries, not necessarily training examples. When a retrained reference exists, compare answer behaviour with that reference on both sets. Otherwise, state the chosen behavioural target explicitly: refusal, reduced verbatim reproduction, lower target-answer probability, or reduced performance on a capability benchmark.

Each target answers a different question. A refusal on the original wording does not establish removal under paraphrase. A fact may remain inferable from permitted information. Conversely, deleting records correctly need not stop the model from making that inference. Robust evaluation should therefore vary prompts and access conditions, and test whether fine-tuning restores the targeted behaviour. Fast recovery is a warning sign relative to a suitable baseline, not by itself proof that the exact original information remained stored unchanged.

When several models teach each other

All of the above corrects one model. At the edge that is often not the deployment. A server-side teacher and a set of smaller on-device students exchange outputs round after round, and each transfer copies some of what the teacher knows into models the deletion request never named. Correcting the teacher is then necessary and not sufficient: the next upload from a student that learned the removed material teaches it back.

This is a structural problem rather than an optimisation one, and it has a structural handle. The transfers that spread the knowledge are transfers the server performed, so the server can read their record. builds a lineage graph from that record, counts how many times a residual will be copied onward, and corrects the smallest set of holders that bounds what survives.

How to evaluate an unlearning claim

Keep forgetting, utility, and cost separate

The most useful comparison includes the original model, a no-op baseline, retain-only fine-tuning, full retraining, and the proposed method. Run them on the same request and define how hyperparameters were selected. Where training is random, repeat runs and report variation. A method should not be allowed to choose a favourable retraining run while its competitors are averaged over seeds.

For a classification dataset \(\mathcal{B}\), define accuracy as

\[ \mathrm{Acc}(\boldsymbol{\theta};\mathcal{B})= \frac{1}{|\mathcal{B}|}\sum_{(\mathbf{x},y)\in\mathcal{B}} \mathbf{1}\{f(\mathbf{x};\boldsymbol{\theta})=y\}. \]

Here \(f\) returns a predicted class and the indicator \(\mathbf{1}\{\cdot\}\) equals one when its statement is true and zero otherwise. Forget accuracy evaluates this quantity on \(\mathcal{D}^{\textrm{f}}\); retain accuracy evaluates it on \(\mathcal{D}^{\textrm{r}}\). A separate held-out test set checks generalisation.

For retraining-based deletion, a useful reported quantity is the forget-accuracy gap

\[ \left|\mathrm{Acc}(\boldsymbol{\theta}^{\textrm{unl}};\mathcal{D}^{\textrm{f}}) -\mathrm{Acc}(\boldsymbol{\theta}^{\star};\mathcal{D}^{\textrm{f}})\right|. \]

Suppose a deleted cat photograph resembles thousands of retained cat photographs. The retrained model may still classify it correctly. Forcing the unlearned model to misclassify it would increase this gap. This example explains the reference-dependent target; it does not turn a small accuracy gap into a complete unlearning test. Models can have the same aggregate accuracy and very different confidence, memorisation, or subgroup errors.

Putting those pieces together produces a specific shape of result table, and it is worth seeing one. reports four quantities side by side, each for three request types, and each plotted twice: once as its own value, and once as the signed distance from the retrained model. The second axis is the one that carries the argument. A bar that beats retraining on forget accuracy has not won; it has over-deleted.

Membership inference needs a clearly specified experiment

A membership inference attack attempts to distinguish training members from nonmembers using accessible model information. In an unlearning experiment, specify whether the attacker is trying to identify original members, currently retained members, or deleted records. Also specify whether it sees only predictions, the weights, or both old and new model versions. These are different experiments.

An area under the receiver operating characteristic curve of 0.5 indicates chance ranking for that attack and dataset. It is not a theorem that every retrained baseline has AUC 0.5. Distribution mismatch, attack calibration, and the definition of positive examples can move the baseline. Compare against an actually retrained model under the same protocol, and report attack power, not just failure to detect a difference. The true-positive rate at low false-positive rates can reveal risks hidden by average metrics.

Include the work done before and after deletion

Measure deletion latency, total computation, retained state, and any recovery stage. For a federated method, include transmitted bytes, communication rounds, and which clients must be online. For a sharded method, include extra training, checkpoints, and inference overhead. A method that is fast only because it stored a large training history has made a legitimate trade, but that storage belongs in the comparison.

On a wireless deployment the comparison is tighter than it looks, because unlearning does not get a budget of its own. It competes for the same bandwidth, energy, and deadline as the training it interrupts, which is the planning problem we study separately for federated split learning. A deletion method evaluated on an idle cluster can behave differently when it has to share a round with the service it is repairing.

Finally, test stress cases: many deletions at once, a rare subgroup, repeated requests, and later fine-tuning. Relearning experiments should give the unlearned and retrained models the same new examples and compute budget. Goel et al. argue for adversarial evaluation rather than relying on a convenient fixed test. Strong empirical evidence narrows the failures we have checked; it does not establish a distributional statement for every possible observer.

Verification and privacy during deletion

A final model does not reveal its full history

A low forget accuracy or a failed attack is an observation about one delivered model. A formal guarantee is a property of a specified algorithm over its possible runs. Thudi et al. show why matching model outputs or inspecting a training trace is insufficient in general to establish that particular records were absent: different training data and procedures can be consistent with the same observed result.

This does not make every audit impossible. It means an audit must state what evidence is available and what it establishes. A behavioural probe tests a behaviour; a verifiable execution mechanism can attest to a specified computation under its assumptions; a deletion guarantee relates that computation to a training reference. These layers should not be substituted for one another.

Sommer et al. study probabilistic verification using deliberately introduced backdoor behaviour. The idea is to test whether a trace associated with a user's contribution remains after deletion. Such a test has assumptions and detection errors. Failure to trigger the backdoor does not establish that every influence of the user's data has disappeared.

The change between model versions can leak information

The two-sided guarantee in Definition 2 concerns the final model's marginal distribution. It does not automatically bound what an attacker learns from the pair of original and unlearned models. The original model already depends on the deleted records, and the change can make their contribution easier to isolate. An observer who held a copy of yesterday's model and downloads today's is looking at a difference computed, in part, from exactly the data that was supposed to disappear.

Chen et al. examine membership leakage from the before-and-after comparison. Hu et al. investigate recovery of features with white-box access to both models and inference of labels using their prediction changes under a different attack setup. The access distinction matters when deciding which threat a deployed system faces, and it is sharper in federated learning, where per-round updates are visible to a server or to a participant by design.

There is also a resource-exhaustion risk. Marchant et al. construct poisoning attacks that make subsequent removal expensive, including triggering costly retraining in a certified-removal system. Thus the evaluation should consider not only the average benign request, but also how the mechanism behaves on adversarially chosen data and deletion workloads.

Repeated requests and continued learning

Track what accumulates

In a fixed dataset with no new arrivals, let \(\mathcal{D}_i^{\textrm{f}}\) be the records named by deletion request \(i\), and let \(\mathcal{D}_i^{\textrm{r}}\) be the records remaining after processing it. Start with \(\mathcal{D}_0^{\textrm{r}}=\mathcal{D}\) and require \(\mathcal{D}_i^{\textrm{f}}\subseteq\mathcal{D}_{i-1}^{\textrm{r}}\). Then

\[ \mathcal{D}_i^{\textrm{r}}=\mathcal{D}_{i-1}^{\textrm{r}}\setminus\mathcal{D}_i^{\textrm{f}},\qquad \boldsymbol{\theta}_i^{\star}=\mathcal{A}(\mathcal{D}_i^{\textrm{r}}). \]

The subscript \(i\) identifies a request; training rounds still use \([t]\). This reference must be reconsidered when new data arrive or the training procedure changes. A guarantee proved for a fresh original model and one fixed request cannot simply be invoked again after every approximate edit. The input model now has a different history, and the next request may have been selected after observing earlier outputs.

Some methods maintain a bound on accumulated residual error and retrain when a threshold is exceeded. More broadly, deletion capacity asks how many deletions can be supported at a stated utility and guarantee level. Sequential deletion is not an untouched problem: Descent-to-Delete studies long sequences of adversarial updates for convex objectives and distinguishes guarantees on all maintained state from guarantees on observable outputs. Those assumptions and distinctions should be retained when discussing extensions to deep or federated models.

Deletion is not the end of training

The equations above assume a fixed dataset. A deployed system rarely offers one. A self-improving agent network keeps collecting trajectories after deployment and keeps training on them, so a record deleted today was already an input to the rollouts collected yesterday, and those rollouts are retained data that nobody has asked to remove. Clearing the current residue is correct and temporary: the influence returns through the retained trajectories it shaped.

The system in treats that return path as the object to be controlled. The server keeps a ledger of which version and which clients produced each trajectory, which is enough to estimate how strongly a deleted record shaped later data. The erasure step clears what is in the model now; a containment step then down-weights the retained trajectories whose influence is highest, so the echo does not come back on the next round.

Continued learning requires a precise comparison

There is an important qualification to the claim that “later training makes the guarantee disappear.” If two model distributions satisfy an exact or approximate comparison and the same randomised continuation is applied to both, using only permitted information, post-processing preserves that comparison. Later computation by itself is not a counterexample to a valid guarantee.

Problems arise when the continuation uses forgotten records, stale optimiser state, cached representations, old checkpoints, or request-dependent information that was not covered by the original guarantee. The agent-network case above is exactly this: the continuation trains on data that the deleted records helped generate, which is not permitted information under the reference, so post-processing does not apply and the guarantee has to be restated. A behaviour removed by a heuristic method may also return because the method never established such a guarantee. Finally, the retain-only reference can itself learn similar knowledge from newly permitted data. That is different from recovering the influence of a deleted record.

For continued federated learning, the practical research question is therefore specific: what state is retained, what information future clients supply, what the evolving reference is, and what an observer can see across time. A useful experiment evaluates both deletion quality and utility after each later training stage, against a reference with the same permitted information. These are the issues developed further in the federated unlearning note.

What to take away

When reading a new unlearning paper, including ours, four questions settle most of it.

  1. What is the reference? Name the training algorithm and the request. Without both, “unlearned” is not yet a claim.

  2. What does the method need? Access to the forget data, stored updates, a lineage record, remaining clients online, a measurement campaign. These conditions decide whether it can run at all, and they are part of its cost.

  3. How strong is the guarantee, exactly? A distributional statement, a bound on an accounted residual, or empirical evidence on the tasks tested. The three are not interchangeable, and the third is the most common.

  4. What happens next? Repeated requests, continued training, and an observer who sees more than the final model. A guarantee proved once for a fresh model is not a property the system keeps for free.

The chapters above collect the ways the answers change with the setting. Our own figures show that the hard part is usually not the update rule. It is deciding what the request means on a map or a trajectory store, finding the data when nobody can name it, and keeping the removal from being undone by the system's own next round.
